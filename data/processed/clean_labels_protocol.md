# Clean-Label Calibration Protocol

## Purpose

This protocol governs the manual review of heuristic risk labels for a small
calibration subset. The goal is to check whether the automated red-flag labels
align with human judgment, enabling optional temperature-scaled probability
calibration.

> **This is NOT a fraud investigation.** Reviewers are checking whether the
> heuristic label (Low / Medium / High risk) is a *reasonable* risk
> classification given the observable procurement data.

---

## Data Source

- **Calibration samples come from `val_calibration` only.**
- `val_calibration` is the newest temporal slice of `train_data/`.
- **No sample is drawn from `test_data/`** — that partition is sealed until
  final evaluation.

### Sample Selection

- 100 rows are drawn via stratified sampling (proportional to class
  distribution in `val_calibration`).
- Stratification preserves the Low / Medium / High risk ratio.
- Random seed is fixed at 42 for reproducibility.

---

## Review Instructions

### For each row, the reviewer should:

1. **Read the procurement context:**
   - Tender title, buyer name, supplier name
   - Tender value and award value
   - Procurement method and number of tenderers
   - Publication date

2. **Examine the triggered red flags:**
   - `flag_single_bidder`: Was there only 1 tenderer?
   - `flag_short_title`: Is the title suspiciously short (< 20 chars)?
   - `flag_short_description`: Is the description sparse (< 60 chars)?
   - `flag_q4_timing`: Was this published in Q4 (Oct-Dec)?
   - `flag_price_deviation`: Is the award/tender ratio ≤ 0.7 or ≥ 1.0?
   - `flag_high_value`: Is the value above the 90th percentile?
   - `flag_direct_procurement`: Was the method "direct" or "limited"?

3. **Compare the heuristic `risk_label` with your judgment:**
   - 0 = Low Risk (0 flags triggered)
   - 1 = Medium Risk (1-2 flags triggered)
   - 2 = High Risk (3+ flags triggered)

4. **Fill in the review columns:**

| Column | Values | Description |
|--------|--------|-------------|
| `verified_label` | 0, 1, or 2 | Your assessed risk level |
| `confidence` | `high`, `medium`, `low` | How confident you are |
| `notes` | Free text | Any reasoning or caveats |

### Important guidelines:

- If you **agree** with the heuristic label, set `verified_label` = `risk_label`.
- If you **disagree**, set `verified_label` to your assessment and explain in `notes`.
- If you **cannot determine** the correct label, leave `verified_label` as blank/NaN
  and set `confidence` = `low`. These rows will be excluded from calibration.
- **Do not** research beyond the information provided in the sheet.

---

## Minimum Threshold for Temperature Scaling

| Condition | Action |
|-----------|--------|
| ≥ 80 rows with `confidence` = `high` and `verified_label` filled | **Enable** temperature scaling in Task 16 |
| < 80 high-confidence rows | **Skip** temperature scaling; ship uncalibrated probabilities; document limitation in Bab 2 and Bab 4 |

---

## Output

- **Input file**: `data/processed/calibration_sheet_100.csv` (generated by Task 14)
- **Output file**: `data/processed/clean_labels_100.csv` (completed by Task 15)
- The output file is the same CSV with the review columns filled in.

---

## Honest Limitations

1. These labels are **heuristic risk indicators**, not confirmed fraud outcomes.
2. Some red flags (e.g., single bidder, Q4 timing) are **correlated with**
   features used by the model, creating a known circularity risk.
3. The review is limited in scope — it does not constitute a forensic audit.
4. Temperature scaling on heuristic labels improves probability calibration
   only relative to the heuristic definition of risk, not relative to
   ground-truth fraud outcomes.
